What's in your kit

2 min

From your LAFVIN ESP32 Basic Starter Kit, you only need a few parts. Put the rest back in the box so the table stays clear.

Use these

  • ESP32 dev board (the black foam it came in is just packaging)
  • USB cable from the kit
  • DHT11 (blue module, 3 pins) for temperature and humidity
  • 1 pushbutton (any color) for SOS
  • Jumper wires: 5 male-to-female, 2 female-to-female
  • The breadboard (for the button and a shared 3V3 spot)
  • Your phone (for its hotspot) and your laptop

Leave these in the box

  • White dome PIR motion sensor (the code expects a different sensor, see below)
  • Blue 2-channel relay (bonus feature, later)
  • OLED screen, LEDs, buzzer, knob, resistors, other modules
About motion: the code is written for an HC-SR04 ultrasonic sensor (two silver "eyes"). Your kit doesn't have one. Skip motion. The box still works: "minutes still" just keeps counting up, which is what the demo shows anyway. Using the PIR would need a code change, so ask your teammate if you want it.
1

Set up the laptop

20 min

The Arduino IDE is the app that sends code to the board. You install it once.

Install Arduino IDE 2

  1. Go to arduino.cc/en/software.
  2. Download the Windows installer, run it, accept the defaults.
  3. If Windows asks to install drivers during setup, click Install.
Arduino IDE opens with an empty sketch that has setup() and loop().

Teach Arduino about the ESP32

  1. File → Preferences.
  2. In Additional boards manager URLs, paste this and click OK:
https://espressif.github.io/arduino-esp32/package_esp32_index.json
  1. Click the Boards icon on the left (second icon). Search esp32.
  2. Install esp32 by Espressif Systems. It's big, so give it a few minutes.
The esp32 entry says INSTALLED.

Install the temperature sensor library

  1. Click the Library icon on the left (third icon). Search DHT sensor library.
  2. Install the one by Adafruit.
  3. When it asks about extra libraries, click Install all.
"DHT sensor library" and "Adafruit Unified Sensor" both say INSTALLED.

Plug in the board and find its port

  1. Plug the kit's USB cable into the ESP32 and your laptop. A red power light on the board turns on.
  2. Open Device Manager (right-click Start).
  3. Open Ports (COM & LPT). Look for Silicon Labs CP210x or USB-SERIAL CH340, followed by a name like COM5. Write that COM number down.
You see a new COM port appear when you plug the board in, and disappear when you unplug it.
No COM port?

1. Try another USB cable. Many cables only charge and don't carry data. This is the most common problem.

2. If you see an unknown device with a yellow warning sign, install the driver: CP210x driver or CH340 driver. Read the small chip near the USB port to know which one.

3. Try another USB port on the laptop, not a hub.

First upload: blink a light

10 min

This proves the laptop can talk to the board, before any wires are involved.

Pick the board and port

  1. Tools → Board → esp32 → ESP32 Dev Module.
  2. Tools → Port → the COM number from the last step.
The bottom-right corner of the IDE says ESP32 Dev Module on COM….

Upload Blink

  1. File → New Sketch. Delete everything and paste this:
void setup() {
  pinMode(2, OUTPUT);          // the small blue light on the board
  Serial.begin(115200);
}
void loop() {
  digitalWrite(2, HIGH); delay(500);
  digitalWrite(2, LOW);  delay(500);
  Serial.println("blink");
}
  1. Click the → Upload arrow (top left). If it asks to save, save anywhere.
  2. When the bottom shows Connecting....., press and hold the BOOT button on the board until numbers start counting up, then let go.
  3. Open Tools → Serial Monitor and set the dropdown on the right to 115200 baud.
A small blue light on the board blinks once a second, and the Serial Monitor prints blink over and over.
It failed or prints garbage

"Failed to connect" / "Wrong boot mode": upload again and hold BOOT the moment you see Connecting......

Weird symbols in the Serial Monitor: the baud dropdown isn't 115200.

"Port busy": close any other program using the board, unplug, plug back in.

Wire it up

45 min
Unplug the USB cable now. Wire with the board unpowered. Everything here is 3.3 volts. It can't shock you, and nothing goes near a wall outlet.

You'll connect 7 wires, one at a time, each with its own color. Breadboard column 30 is a shared 3V3 spot, because your board has only one 3V3 pin and two things need it.

Get your 7 wires ready

  1. From the male-female ribbon, peel off: red, orange, blue, brown, green. That's 5.
  2. From the female-female ribbon, peel off: yellow and black. That's 2.
  3. Lay all 7 in a row on the table, in the order red, orange, yellow, black, blue, brown, green. That's wire 1 to wire 7.
7 loose wires in a row, and each one has the right ends (check against the ribbon picture).

Lay the ESP32 flat and find its 6 pins

The ESP32 does not go into the breadboard (it's too wide). Lay it flat on the table, labels facing up, USB plug pointing toward you. The pins point down into a book or folded cloth underneath, so they don't scratch the table. If the board wobbles, that's fine.

  1. Right side (USB toward you): count from the corner pin by the USB. Corner = 3V3 (red). 1 up = GND (black). 4 up = D4 (yellow).
  2. Left side: corner = VIN, never use it. 1 up = GND (brown). 5 up = D27 (blue). 6 up = D26 (green).
  3. Female ends push onto the pins from underneath. Easiest way: hold the board at the edge of a book so the pins hang over the edge, or flip it (see the back photo).
Never put anything on VIN. It's the left corner pin by the USB, right next to the brown wire's GND.

Wire 1 (RED): 3V3 → j30

Am I in the right hole? Check all four before moving on:
  1. Number check: lay a card or your phone's straight edge on the board, lined up with the printed number, and run it straight down. The holes along that edge are that column. The camera angle makes numbers look "between" holes in photos; from straight above they aren't.
  2. Count check: for unnumbered columns (like 12), count holes from the nearest printed number: 10, 11, 12.
  3. Row check: rows a–e and f–j are the 5 rows on each side of the middle gap. The striped rail rows along the edges are never used.
  4. Seated check: no metal showing, and a gentle tug doesn't pull it out.

For column 30, the exact number matters less than this: red, orange and green share one column on the same half. If they're together, they're connected.

  1. Take the red male-female wire.
  2. Push its female end onto 3V3: right side of the ESP32, the corner pin right by the USB.
  3. Push its male end into breadboard hole j30: find 30 on the long edge, then the outermost row on the f–j side.
Red wire from the 3V3 corner pin to j30. No metal showing at either end.

Wires 2, 3, 4 (ORANGE, YELLOW, BLACK): the temperature sensor

  1. Orange male-female: female end onto the sensor's middle pin (+). Male end into breadboard i30, the hole right next to the red wire in j30, one row in.
  2. Yellow female-female: one end onto the sensor's bottom pin (S). Other end onto ESP32 D4: right side, 4 pins up from the 3V3 corner.
  3. Black female-female: one end onto the sensor's top pin (−). Other end onto ESP32 GND: right side, 1 pin up from the 3V3 corner, right above the red wire.
The sensor has orange in the middle, yellow on the S side, black on the other end. The right side of the ESP32 has, from the USB corner up: red, black, (2 empty pins), yellow.
The blue module already has the extra resistor built in. You don't need one.

The SOS button + wires 5, 6 (BLUE, BROWN)

  1. Take any one big button from the kit (the square black switch with a colored cap; cap color doesn't matter, leave the cap on). Look at it from the side: its 4 legs come out of two opposite sides, 2 legs per side.
  2. Hold it over the breadboard's middle gap, one pair of legs in holes e10 and e12, the other pair in h10 and h12. The button is wide, so it reaches across the gap to row h. Column 11 stays empty under it.
  3. Press straight down with your thumb until it sits flat. Legs won't line up? Turn it a quarter turn and try again.
  1. Blue male-female: male end into a10 (column 10, outermost row on the a–e side, straight out from the button's e10 leg). Female end onto ESP32 D27: left side, 5 pins up from the VIN corner.
  2. Brown male-female: male end into j12 (column 12, outermost row on the f–j side, same column as the h12 leg). Female end onto ESP32 GND: left side, 1 pin up from the VIN corner. Not VIN itself.
Blue goes from the top-left corner of the button area to D27. Brown goes from the bottom-right corner to the left GND. The legs sit in e10, e12, h10, h12.

Wire 7 (GREEN): the power-grid stand-in

  1. Green male-female: female end onto ESP32 D26: left side, 6 pins up from the VIN corner, the pin right above the blue wire.
  2. Male end into breadboard h30: column 30, the hole right next to orange in i30, one more row in.
Column 30 now holds, from the edge in: red (j30), orange (i30), green (h30).
This green wire is "the wall power." While it's in h30, the box thinks the grid is on. For the demo you pull its male end out of h30, and say on camera: "this wire stands in for the wall-power sensor."

Check all 7, then take your Devpost photo

  1. Go down the table at the top of this phase, one row at a time. Touch each wire and follow it end to end with your finger.
  2. ESP32 right side, from the USB corner up: red, black, empty, empty, yellow.
  3. ESP32 left side, from the USB corner up: VIN empty, brown, empty, empty, empty, blue, green.
  4. No metal showing at any connection. Nothing on VIN.
  5. Take a clear photo from straight above, in good light. That's your wiring photo for Devpost (save it as docs/wiring.jpg). Send it here too and I'll check it.

Test each part alone

20 min

Small tests first. If the full program fails later, you'll already know the wiring is fine.

Temperature test

  1. Plug the USB back in.
  2. File → Examples → DHT sensor library → DHTtester.
  3. Change #define DHTPIN 2 to #define DHTPIN 4.
  4. Find the 3 DHTTYPE lines (around lines 15–17). Make only DHT11 active: no // in front of the DHT11 line, and // in front of both the DHT22 and the DHT21 lines. It should read:
#define DHTTYPE DHT11   // DHT 11
//#define DHTTYPE DHT22   // DHT 22  (AM2302), AM2321
//#define DHTTYPE DHT21   // DHT 21 (AM2301)
  1. Plug in the USB. Check the top bar dropdown says ESP32 Dev Module with a USB symbol (if it says "No port", click it and pick your COM port).
  2. Click the round → arrow (second button, top left). When the Output panel says Connecting....., hold BOOT (right of the USB plug) until percentages count up. Done when it says Hard resetting via RTS pin....
  3. Click the magnifying-glass icon (top right) to open the Serial Monitor. Set its dropdown to 115200 baud.
Every two seconds: Humidity: 55.00% Temperature: 23.00°C 73.40°F …. Cup your hands around the sensor and breathe on it. The numbers go up.
"Failed to read from DHT sensor!"

Unplug, check the S/DATA wire is on D4, + is in i30, the 3V3 wire is in j30, and − is on GND. Make sure you edited the DHT11 line, not just the pin.

Button and grid test

  1. File → New Sketch, paste this, and upload:
void setup() {
  Serial.begin(115200);
  pinMode(26, INPUT_PULLDOWN);   // grid jumper
  pinMode(27, INPUT_PULLUP);     // SOS button
  pinMode(2, OUTPUT);
}
void loop() {
  bool grid = digitalRead(26) == HIGH;
  bool sos  = digitalRead(27) == LOW;
  digitalWrite(2, sos);
  Serial.printf("grid=%s   button=%s\n", grid ? "ON" : "OFF", sos ? "PRESSED" : "-");
  delay(300);
}
With the green wire in h30: grid=ON. Pull it out of h30: grid=OFF. Hold the button: button=PRESSED and the blue light turns on.
Button always "-" (never PRESSED)

1. Skip-the-button test (safe with USB plugged in, it's only breadboard holes): move the blue wire's male end from a10 into i12, the same column as brown. If the viewer now says PRESSED, the wires are right and the button isn't making contact. If it still says "-", unplug USB and check blue is on D27 (left side, 5 pins up from VIN) and brown on GND (left side, 1 pin up from VIN).

2. Reseat the button: put blue back in a10. Pull the button out, straighten any splayed leg, push it back into e10, e12, h10, h12 and press hard on the switch body until it sits flat, not floating. Press it in the middle: you should feel a small click.

Always PRESSED: the blue wire's hole is touching brown's column somewhere. Check blue is in a10 and brown in j12.

Load the real Nightlight program

30 min

First the box sends to a free test inbox on the web, so you can see packets arrive without worrying about the server.

Turn on your phone's hotspot

  1. Turn on Personal Hotspot.
  2. iPhone: turn on Maximize Compatibility. The ESP32 only sees 2.4 GHz WiFi.
  3. Note the hotspot name and password exactly, including capital letters.

Open a test inbox

Go to webhook.site. It gives you a unique URL like https://webhook.site/1234abcd-…. Copy it and leave the tab open.

Make config.h

  1. In VS Code (not File Explorer, which hides file endings), open firmware/nightlight_esp32/.
  2. Right-click config.example.h → Copy, then right-click the folder → Paste.
  3. Rename the copy to exactly config.h.
  4. Fill in these four lines:
#define WIFI_SSID     "your hotspot name"
#define WIFI_PASS     "your hotspot password"
#define API_URL       "https://webhook.site/your-unique-id"
#define INGEST_KEY    "same value as INGEST_KEY in .env (line 13)"

Leave the other lines alone. Save with Ctrl+S.

config.h is ignored by git, so your hotspot password won't be uploaded.

Open and upload the Nightlight sketch

  1. In Arduino: File → Open → firmware/nightlight_esp32/nightlight_esp32.ino. You'll see tabs for config.h and packet.h too.
  2. Check that Board says ESP32 Dev Module and the port is right.
  3. Upload (hold BOOT if needed), then open the Serial Monitor at 115200.
You see wifi connected, then every 5 seconds a line like this:
01 01 00 00 … (24 B) T=74.1F RH=52% HI=74.3F tier=0 grid=1 sos=0 dark=0min still=15min cm=-1
POST seq 0 -> 200

cm=-1 is expected, because there's no ultrasonic sensor. still climbs fast because the demo clock runs 900× faster than real time.

Something's off in the Serial Monitor

"no wifi, queued": hotspot name or password typo, the iPhone isn't on Maximize Compatibility, or the phone screen locked. Keep the hotspot screen open.

Upload error about config.h: the file isn't named exactly config.h, or it isn't in the same folder as the .ino.

POST -> -1: the phone has no data, or the URL is wrong.

"DHT read failed": recheck the D4 wire and the i30/j30 wires.

Watch packets arrive

On webhook.site, a new request shows up every 5 seconds with a body like {"p":"AQEAAA…"}. That's your real device sending real data over the internet.
This is your safety net. If the next phase fights you, you can already film the Serial Monitor and webhook.site side by side.
6

Send to the Nightlight map on your laptop

30 min

Now the packets go to the app running on your laptop instead of webhook.site, and your box appears as a dot on the map. Later you'll swap in the Nebius address the same way.

Put the laptop on the phone's hotspot

The board and the laptop have to be on the same network. Connect your laptop's WiFi to the phone hotspot.

Start the app so the board can reach it

Open a PowerShell terminal in VS Code and run:

cd cloud
.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

The --host 0.0.0.0 part matters. Without it, only the laptop itself can reach the app, and the board gets nothing.

If Windows asks "Allow access?" for Python, tick both Private and Public and click Allow. Phone hotspots often count as public networks.
You can open localhost:8000 in your browser and see the map.

Point the board at your laptop

  1. In a second terminal, run ipconfig. Under Wireless LAN adapter Wi-Fi, copy the IPv4 Address (like 172.20.10.4).
  2. In config.h, change API_URL:
#define API_URL       "http://172.20.10.4:8000/v1/ingest"
  1. Use your IP address and plain http, not https. Save, upload again.
The Serial Monitor shows POST seq … -> 200, and the uvicorn terminal logs POST /v1/ingest 200.
Not getting 200

-> 401: INGEST_KEY in config.h doesn't match line 13 of .env. Copy it again exactly.

-> -1: wrong IP, the laptop isn't on the hotspot, uvicorn was started without --host 0.0.0.0, or the firewall blocked it. Check Windows Security → Firewall → Allow an app and allow Python.

-> 400: the sketch doesn't match packet.h. Reopen the .ino from the repo and upload again.

Find your box on the map

Open localhost:8000. A dot for unit 1 appears, marked as the real device, and updates every 5 seconds.

Dress rehearsal

15 min

This is the hardware minute from docs/DEMO.md. If all four work, you're ready to film.

Cut the power

Pull the green grid wire out of breadboard hole h30.

The blue light on the board stays solid on. Within 5 seconds, the map shows grid OFF and hours dark start counting. Push it back into h30 and it clears.

Make it hot

Cup your hands around the DHT11 and breathe warm air on it for 20–30 seconds.

T= and HI= go up in the Serial Monitor, and the home's risk on the map rises.

Press SOS

The blue light blinks fast. The map row turns red with SOS. It stays flagged for 60 seconds.

Run it three times in a row

Reset by pressing the board's EN (or RST) button, then repeat g1 to g3. Three clean runs means you're ready to film.
